1. 两数之和（Two Sum）
----------------------
识别特征：
遍历数组时，需要寻找与当前元素互补的另一个元素。

关键思路：
遍历当前值 x，计算 need = target - x，通过 unordered_map 查找 need 是否出现过。找到后返回两个下标。

优化本质：
哈希表把两层枚举优化为一次遍历，平均时间复杂度 O(n)，空间复杂度 O(n)。

易错点：
- 先查找，再插入当前元素，避免同一个元素使用两次。
- 理解 unordered_map 中 key 和 value 的含义。
- 理解 find() 与 end() 的区别。

个人学习过程：
主要困难不是数学公式，而是 C++ STL 的使用：
- unordered_map 的 key 存什么，value 存什么。
- find(need) 返回什么。
- end() 代表什么。
- mp[need] 为什么能够得到下标。
后来理解为：哈希表存储“数值 -> 下标”，先查历史元素，再插入当前元素。
交接记录没有保留用户最初完整的暴力代码，因此不要虚构暴力尝试。

49. 字母异位词分组（Group Anagrams）
------------------------------------
识别特征：
多个字符串经过规范化后具有相同特征，需要归为一组。

关键思路：
将字符串排序，排序后的字符串作为 unordered_map 的 key，原字符串放入对应的 vector。

优化本质：
把两两比较转为规范化后分组。

易错点：
- unordered_map<string, vector<string>> 的嵌套类型。
- sort() 的参数。
- push_back() 的使用。
- auto& 可避免不必要的复制。

个人学习过程：
数学识别相对直接，主要困难在 STL 语法。后来明确理解：排序后的字符串只是分组 key，真正保存的是原字符串。

128. 最长连续序列（Longest Consecutive Sequence）
-------------------------------------------------
识别特征：
无序数组中寻找最长连续整数段。

关键思路：
先将元素放入 unordered_set。只有当 x-1 不存在时，才从 x 开始向右扩展。

优化本质：
只从连续序列的起点开始统计，避免重复遍历。

易错点：
- find() != end() 判断存在。
- 局部变量作用域。
- 整数边界。

个人学习过程：
曾遇到序列起点判断、find()/end() 及局部变量作用域问题。后来理解，只有前一个数不存在，当前数才有资格作为序列起点。例如 1、2、3、4，只需要从 1 开始扩展一次。

283. 移动零（Move Zeroes）
--------------------------
识别特征：
原地移动特定元素，同时保持其他元素的相对顺序。

关键思路：
使用扫描指针读取数组，写入指针指向下一个非零元素应该放置的位置。

优化本质：
不使用额外数组，一次扫描完成，O(n) 时间、O(1) 额外空间。

易错点：
区分扫描指针和写入指针的职责；注意原地覆盖与交换的区别。

个人学习过程：
最初曾用“栈”来理解移动零：把非零数字依次保留下来，最后让零集中到尾部。
后来明确了题目要求原地修改，理解可以直接利用数组自身作为写入区域，不需要额外栈或容器。
复习时应能解释为什么非零元素的相对顺序仍然保持不变。

11. 盛最多水的容器（Container With Most Water）
------------------------------------------------
识别特征：
左右两根柱子形成容器，面积受较短柱子的高度限制。

关键思路：
计算当前面积后，移动高度较短的一侧。
area = min(height[left], height[right]) * (right - left)

优化本质：
通过贪心排除不可能产生更大面积的短边，O(n)。

易错点：
面积使用较短柱子的高度，而不是较高柱子的高度；宽度是 right-left。

个人学习过程：
关键疑问是：为什么每次移动较短边，而不是较高边？
后来理解：较短边已经限制当前容器高度，保留它只会继续缩小宽度，因此可以安全舍弃短边。移动较高边无法突破当前短边造成的高度限制。

15. 三数之和（3Sum）
--------------------
识别特征：
寻找多个元素满足固定和，且不能产生重复答案。

关键思路：
排序，固定一个数，剩余部分用左右双指针寻找相反数。

优化本质：
将三重枚举降低为 O(n²)。

易错点：
三处去重：
1. 固定值 nums[i] 与前一个相同则跳过。
2. left 从 i+1 开始。
3. 找到答案后，左右指针都需要跳过重复值。

个人学习过程：
主要卡在重复答案的控制，而不是双指针本身。
三处去重都需要能解释各自防止哪一种重复。曾重点使用 [-1,0,1,2,-1,-4] 手推结果。
这题应列为重点复习对象。

3. 无重复字符的最长子串（Longest Substring Without Repeating Characters）
----------------------------------------------------------------------------
识别特征：
寻找满足窗口内字符不重复的最长连续子串。

关键思路：
滑动窗口，right 扩展；出现重复时，left 不断右移，直到窗口重新合法。

优化本质：
避免重复扫描所有子串，O(n)。

易错点：
- 出现重复需要 while，而不只是 if。
- 注意 right 的变量作用域。
- 每次窗口合法后更新答案。
- 子串必须连续。

个人学习过程：
曾混淆 if 与 while：发现重复字符后只移动一次 left，可能仍然存在重复字符。
后来理解：只要窗口条件不满足，就持续收缩，直到恢复合法；随后更新最长长度。
复习可用 abcabcbb 或 abba 手推窗口。

438. 找到字符串中所有字母异位词（Find All Anagrams in a String）
--------------------------------------------------------------------
识别特征：
固定长度窗口内的字符组成需要与目标字符串相同。

关键思路：
使用两个长度为 26 的频次数组，分别记录目标字符串和当前窗口的字符数量。
窗口右移时，离开的字符计数 -1，进入的字符计数 +1。

优化本质：
避免对每个窗口重新排序；窗口更新只涉及两个字符计数。

易错点：
- 数组初始化。
- 字符映射 x-'a'。
- 窗口长度和越界判断。
- 比较全部 26 项。
- p.size() > s.size() 的边界情况。
- 范围 for 中的 x 是字符，不是数组下标。

个人学习过程：
最初考虑过枚举 p 的所有排列；也想到对 p 排序，并对 s 中每个等长窗口排序后比较。排序窗口能判断正确，但重复工作很多。
真正卡住的是没有立即想到用 26 个字母的频次数组表达字符组成。
后来理解：维护目标频次数组和窗口频次数组；窗口每右移一格，只让离开的字符 -1、进入的字符 +1，再比较两份频次。
这题属于“能想到方向，但关键优化不是自己推出来”的典型题，优先安排独立重做。

560. 和为 K 的子数组（Subarray Sum Equals K）
------------------------------------------------
识别特征：
统计连续子数组中和等于 k 的数量。

关键思路：
维护前缀和，用 unordered_map 记录历史前缀和出现次数。
当前前缀和为 sum，需要寻找历史前缀和 sum-k：
ans += mp[sum-k]
随后 mp[sum]++。

优化本质：
前缀和将区间和转化为两个前缀和之差，哈希表一次统计所有合法起点。

易错点：
- 初始化 mp[0]=1。
- 必须先查询，再记录当前前缀和。
- 使用频次 map，不能只使用 set。
- 负数存在时不能简单使用普通滑动窗口。

个人学习过程：
最初能联想到前缀和，也考虑过哈希集合。
关键问题是：本题统计的是子数组数量，而不是判断某个前缀和是否存在。
相同的历史前缀和可能对应多个合法起点，因此必须记录出现次数。
一开始没有独立完成，隔一段时间重新练习后才较完整地写出核心代码。
这题需要间隔复习。

53. 最大子数组和（Maximum Subarray）
------------------------------------
识别特征：
求连续子数组的最大和。

关键思路：
Kadane：
当前最大连续和 = max(当前元素, 前一个最大连续和 + 当前元素)。
也可以通过前缀和减去历史最小前缀和实现。

优化本质：
只维护影响未来决策的局部最优，O(n)。

易错点：
- 全负数组不能把答案初始化为 0。
- 前缀和方法中，先计算当前答案，再更新最小前缀和。

个人学习过程：
学习过 Kadane 和前缀和两种路线，但隔几天容易忘记“历史累计为负时重新开始”的判断。
这说明一次听懂不等于能稳定独立提取。需要不看模板，分别解释两种 O(n) 解法。

56. 合并区间（Merge Intervals）
--------------------------------
识别特征：
合并有重叠的区间。

关键思路：
按照左端点排序，依次与结果数组中的最后一个区间比较。
若新区间左端点 <= 当前末尾区间右端点，则合并；否则加入新区间。

优化本质：
排序后只需局部比较，整体 O(n log n)。

易错点：
- ans.empty()
- ans.back()[1]
- 二维 vector 的结构。
- auto& 与范围 for。

个人学习过程：
主要困难是 STL 语法，而不是区间合并规则。
当时需要熟悉 vector<vector<int>>、范围 for(auto& p:intervals)、ans.empty()、ans.back()[1]。
要能区分 ans.back()（一个区间）与 ans.back()[1]（区间右端点）。

189. 轮转数组（Rotate Array）
------------------------------
识别特征：
将数组整体向右旋转 k 位。

关键思路：
k %= n，然后：
1. 整体 reverse。
2. 反转前 k 个元素。
3. 反转剩余元素。

优化本质：
三次原地翻转完成位置交换，不需要额外数组。

易错点：
- k 可能大于 n。
- reverse(begin,end) 的 end 不包含。
- 注意空数组边界。

个人学习过程：
最初考虑直接移动元素，但容易覆盖原数据。
后来理解三次翻转的组合效果。复习时用 [1,2,3,4,5,6,7], k=3 手推每一步。

238. 除自身以外数组的乘积（Product of Array Except Self）
----------------------------------------------------------
识别特征：
每个位置的答案取决于当前位置左右两侧元素的乘积。

关键思路：
先从左向右计算左侧乘积，存入 ans；再从右向左，用 right 变量累积右侧乘积。

优化本质：
不使用除法，利用输出数组保存左侧乘积，额外空间 O(1)（不计输出数组）。

易错点：
反向遍历时，先 ans[i] *= right，再 right *= nums[i]。

个人学习过程：
最初考虑“全部元素乘积 ÷ 当前元素”，但题目禁止除法，而且数组可能有 0。
先使用左右辅助数组计算前缀积、后缀积。
之后用户主动提出能否在 ans 上从左向右扫一遍，再从右向左扫一遍，由此将左侧乘积直接存在输出数组中，再用一个变量 right 累积右侧乘积。
这是一次明确的主动空间优化经历，值得保留。

35. 搜索插入位置（Search Insert Position）
------------------------------------------
识别特征：
有序数组查找目标；若不存在，返回应该插入的位置。

关键思路：
左闭右闭二分：left=0，right=n-1。
找到直接返回 mid；找不到时返回 left。

优化本质：
利用有序性，每轮排除一半，O(log n)。

易错点：
- mid 是下标，nums[mid] 是数值。
- right=n-1。
- while(left<=right)。
- left=mid+1，right=mid-1。

个人学习过程：
需要明确二分区间定义与循环条件之间的关系。后续 34、33、153 都依赖这套基础。
不要只背模板，要说清每次安全排除了什么。

34. 在排序数组中查找元素的第一个和最后一个位置
------------------------------------------------
识别特征：
在有序数组中找重复目标的左右边界。

关键思路：
分别执行两次二分：
- 第一次寻找最左位置。
- 第二次寻找最右位置。

优化本质：
不线性扫描重复元素，O(log n)。

易错点：
- 两次循环独立执行。
- 第二次循环需要重置 left、right。
- 每轮重新计算 mid。
- 注意边界更新，保证搜索范围缩小。

个人学习过程：
曾犹豫两个 while 应该如何组织。第一次二分结束后需要重新初始化 left、right，再开始第二次二分。
后来曾出现超时，原因是 mid 的重新计算有误。
最终理解两个边界应分别寻找，不能混在同一轮循环中。

33. 搜索旋转排序数组（Search in Rotated Sorted Array）
------------------------------------------------------
识别特征：
旋转后的有序数组中查找目标。

关键思路：
用户曾主动提出：
1. 二分找到旋转分界点。
2. 判断 target 所在的有序区间。
3. 在对应区间继续二分。

优化本质：
利用旋转数组的局部有序性，O(log n)。

易错点：
- nums[mid] 与 nums[right] 的关系。
- right=mid 和 right=mid-1 的区别。
- pivot 分段后不能只依赖 target>nums[pivot]。
- 必须明确每轮安全排除哪一半。

个人学习过程：
总体思路是用户自己提出的，但比较条件的推导较困难。
尤其是为什么有时 right=mid，为什么有时 right=mid-1，以及如何选择目标所在区间。
这是用户二分判断的薄弱点，应该与 153 组合复习。

153. 寻找旋转排序数组中的最小值（Find Minimum in Rotated Sorted Array）
----------------------------------------------------------------------------
识别特征：
无重复元素的旋转有序数组中寻找最小值。

关键思路：
比较 nums[mid] 和 nums[right]：
- 若 nums[mid] > nums[right]，left=mid+1。
- 否则 right=mid。
最终返回 nums[left]。

优化本质：
不断排除不可能包含最小值的一半，O(log n)。

易错点：
- right=mid 必须保留 mid。
- 最终返回元素值，不是下标。
- 不能直接套用有重复元素的版本。

个人学习过程：
用户先做了更复杂的 33，后来才做 153。
回头看，153 的“二分找旋转数组最小值”是 33 的前置模型。
后来用户能够独立重新写出该模板。

121. 买卖股票的最佳时机（Best Time to Buy and Sell Stock）
----------------------------------------------------------
识别特征：
先买入后卖出，求最大利润。

关键思路：
维护历史最低价格 minprice，每天计算：
ans=max(ans, prices[i]-minprice)
随后更新 minprice。

优化本质：
一次遍历，O(n) 时间、O(1) 空间。

易错点：
- 不能用全局最高价减全局最低价，因为买卖顺序可能错误。
- 价格一路下降时必须返回 0。
- 历史最低价必须发生在当前卖出日之前或当天。

个人学习过程：
用户主动将本题与 53「最大子数组和」的历史最小前缀思路联系起来。
为了让当前卖出价格与之前买入价格的差最大，需要维护历史最低买入价。

55. 跳跃游戏（Jump Game）
-------------------------
识别特征：
判断从起点能否到达最后一个下标。

关键思路：
维护最远可达位置 far。
先判断 i>far，若成立说明当前位置不可达；否则更新：
far=max(far, i+nums[i])

优化本质：
只维护最远可达边界，O(n) 时间、O(1) 空间。

易错点：
- 先判断可达性，再利用当前位置扩展 far。
- i==far 仍然可达。
- 终点是 n-1。

个人学习过程：
最初联想到递归爬楼梯、倒推，也提到“当前值和下标”“下标差值与前缀和”。后来意识到简单相加前缀和不能描述可达性。
关键转折是从“具体跳到哪里”转向“到目前为止最远能够到哪里”。
初稿曾写 if(i<far) break，条件方向反了；还曾先用 i+nums[i] 更新 far，再判断 i 能否到达，导致可能借用不可达位置的跳跃能力。
最终纠正：先 if(i>far) return false，再 far=max(far,i+nums[i])；只要 far>=n-1 就可以到终点。
修正后 AC。
可迁移原则：先验证状态合法，再利用它扩展搜索边界。

45. 跳跃游戏 II（Jump Game II）
-------------------------------
识别特征：
保证能够到达终点，求最少跳跃次数。

关键思路：
使用三个变量：
- far：下一层最远可达位置。
- end：当前层最远边界。
- step：跳跃次数。
当 i==end 时，当前层搜索结束，step++，并令 end=far。

优化本质：
将 BFS 的分层思想压缩成连续区间边界，O(n)。

易错点：
- far、end、step 初始化为 0。
- 遍历到 n-2，不必从终点再跳一次。
- far 和 end 职责不同。

个人学习过程：
最初认为 far 每更新一次就代表跳了一次，后来发现并不成立。
用户提出直接统计 far 被更新的次数，我们通过反例发现：遍历候选位置更新 far，并不代表真的选择了一次落点。
后来开始区分“当前一次跳跃能到达的范围”和“下一次可拓展的最远范围”。
最终理解：far 记录下一层最远边界，end 记录当前层边界；当 i==end 表示本层候选位置检查完，才 step++ 并 end=far。
初稿把 far、end 都初始化为 nums[0]，step 初始化为 0；还让循环遍历最后一个元素。修正为三个变量都从 0 开始，循环到 i<n-1，之后 AC。

206. 反转链表（Reverse Linked List）
------------------------------------
识别特征：
原地修改单链表的 next 指针方向。

关键思路：
三个指针：
prev=nullptr，cur=head，next。
每轮：
1. 保存 cur->next。
2. cur->next=prev。
3. prev=cur。
4. cur=next。
最后返回 prev。

优化本质：
原地修改指针，O(n) 时间、O(1) 额外空间。

易错点：
- 修改 next 前先保存后继节点，避免断链。
- 区分 p->next 和 p=next。
- 最后返回 prev。

个人学习过程：
用户有数据结构基础，但链表指针语法一段时间没有使用。
曾写出 s=p->next，这是正确且必要的保存后继方式。
随后把 p->next=1，混淆了节点值与节点指针；正确应该写 p->next=prev。
又曾写 prev=s、p=s->next，直接移动到未反转的位置，跳过当前应该处理的节点。
最终顺序：先保存 next=cur->next，再 cur->next=prev，之后 prev=cur、cur=next；prev 初始 nullptr，最终返回 prev。
用户要求直接看完整代码后完成 AC，因此记录为“看完整代码后完成”，尚未验证不看答案能独立复现。

94. 二叉树的中序遍历（Binary Tree Inorder Traversal）
-----------------------------------------------------
识别特征：
按照左子树 -> 当前节点 -> 右子树遍历。

关键思路：
递归 DFS：
1. 递归左孩子。
2. 将当前 root->val 放入结果 vector。
3. 递归右孩子。

优化本质：
利用函数调用栈维护遍历状态。O(n) 时间、O(h) 递归栈空间。

易错点：
- root==nullptr 必须返回。
- 当前递归中的 root 是当前子树的根。
- return 只结束当前函数调用，不会终止所有递归。

个人学习过程：
用户正确回答简单树的中序结果为 2、1、3。
用户主动提出“是不是只有根在进动态数组，当然左右结点也会是根”，由此讨论了递归中左右孩子也会成为下一层调用的 root。
用户还询问先序遍历，并理解将访问根节点的操作放到左递归之前就会变成先序遍历。
对 nullptr 终止条件最初回答不确定，后来理解空指针不能解引用，递归需要在空节点处结束。
用户明确确认 AC。

104. 二叉树的最大深度（Maximum Depth of Binary Tree）
-----------------------------------------------------
识别特征：
求二叉树从根到最远叶子节点的最大深度。

关键思路：
depth(root)=max(depth(root->left), depth(root->right))+1。
空节点返回 0。

优化本质：
后序 DFS，自底向上计算，每个节点访问一次，O(n) 时间、O(h) 递归空间。

易错点：
- 空节点返回 0。
- 左右子树深度取最大值，而不是相加。
- 当前节点要通过 +1 计入深度。

个人学习过程：
用户开始时问“最大深度就是求什么来着”，随后展示代码并明确确认 AC。
当前可访问记录没有保留足够清晰的代码细节，不能编造用户具体写过的错误。
可以记录用户重新回忆最大深度递归关系并完成 AC；具体错误待补充。

226. 翻转二叉树（Invert Binary Tree）
-------------------------------------
识别特征：
对每个节点交换左右孩子。

关键思路：
swap(root->left, root->right)，然后递归翻转左右子树，最后返回 root。

优化本质：
直接修改原树，O(n) 时间、O(h) 递归空间。

易错点：
- 空节点返回 nullptr。
- 交换的是指针，不是 val。
- 函数返回类型是 TreeNode*，最终必须 return root。

个人学习过程：
用户正确理解左右子树交换，并能独立写出主要逻辑。
最终代码只遗漏 return root，之后补齐并 AC。

101. 对称二叉树（Symmetric Tree）
---------------------------------
识别特征：
判断左右两棵子树是否互为镜像。

关键思路：
定义 check(left,right)，同步比较：
- left->left 和 right->right。
- left->right 和 right->left。
两个都为空返回 true，只有一个为空返回 false，节点值不同返回 false。
最后返回两次递归结果的逻辑与。

优化本质：
同步 DFS，O(n) 时间、O(h) 空间。

易错点：
- 先判断空指针，再访问 val。
- 比较节点值，而不是比较指针地址。
- 递归结果必须返回。
- isSymmetric() 返回 bool，不能直接 return root。

个人学习过程：
用户最初比较了 left->left 与 right->right 的指针地址，后来修正为比较节点 val。
还讨论了两个空节点返回 true、只有一个为空返回 false。
用户曾将左右孩子的镜像关系表述为：left 的右孩子对应 right 的左孩子，left 的左孩子对应 right 的右孩子。
之后修正递归布尔返回值，最终 AC。

543. 二叉树的直径（Diameter of Binary Tree）
-------------------------------------------
识别特征：
求任意两个节点之间的最长路径，路径不一定经过整棵树的根。

关键思路：
后序 DFS：
left=maxdepth(root->left)
right=maxdepth(root->right)
ans=max(ans,left+right)
返回 max(left,right)+1。

优化本质：
一次遍历同时完成深度计算和最大直径维护，O(n) 时间、O(h) 空间。

易错点：
- 直径按边数计算。
- 左右子树深度不包含当前节点。
- ans 必须取最大值，不能直接覆盖。
- 递归返回深度，而不是返回直径。

个人学习过程：
用户最初以为深度计算会包含当前 root，因此对边数计算产生混淆。
后来明确区分：
- 节点数 = leftDepth + rightDepth + 1。
- 边数 = leftDepth + rightDepth。
最初只计算经过根节点的路径，忽略直径可能出现在内部子树。
代码初稿中 maxdepth(root) 反复调用相同 root，没有向左右孩子递归，会造成无限递归。
后来调整为分别计算 maxdepth(root->left) 和 maxdepth(root->right)。
用户写出 ans = left + right，但这会覆盖之前找到的最大直径；最终改成 ans = max(ans, left + right)，确认 AC。
这是一次从“只检查根节点”到“遍历每个节点并维护全局最优”的理解变化。
